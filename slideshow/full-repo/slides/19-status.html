Estado do projeto

IMPLEMENTADO
  • Pipeline de dados e catálogo processado
  • Modelos, migrações e seed do catálogo
  • API de health check e criação de sessão
  • Engine headless executável em demo
  • Interface React e animação com dados mock
PARCIAL / DESCONECTADO
  • Serviços de sessão e bracket existem; criação de sessão não chama o bracket
  • Engine produz log em memória; API não o executa
  • Frontend renderiza transmissão mock; não consome a API
  • Heurísticas ainda precisam de validação estatística e regras extras
PLANEJADO
  • Integração entre frontend e endpoints reais
  • Coordenação, persistência e transmissão de partidas
  • Eventos e frames por API e replay
  • Completar regras, testes e calibração

Convenção dos diagramas: linha contínua = fluxo existente · tracejada = integração planejada.

É importante separar o que já existe do que ainda está conectado. Há um BracketService que cria partidas, mas o endpoint atual de sessão não o chama. Há um runner de partidas, mas nenhum serviço de API o executa. E há uma tela de transmissão, mas ela ainda recebe frames simulados no frontend. Essa diferenciação é a mesma que usamos em todas as partes do sistema.
