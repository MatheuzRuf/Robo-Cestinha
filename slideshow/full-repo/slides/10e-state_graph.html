O grafo de decisões de uma posse

Cada posse percorre um grafo de estados, do salto de bola até um resultado final. heuristics.py define o peso de cada aresta; state_machine.py percorre o grafo.

flowchart TB
  HANDLER["Escolhe o condutor
select_ball_handler()"] --> DECIDE{"decide_handler_action()"}

  DECIDE -->|PASS| PASSOUT{"Passe chega?"}
  PASSOUT -->|sim| HANDLER
  PASSOUT -->|"não, interceptado"| TURNOVER

  DECIDE -->|MOVE| MOVEOUT{"Resultado do drible"}
  MOVEOUT -->|"segura a bola / falta sofrida"| DECIDE
  MOVEOUT -->|desarmado| TURNOVER

  DECIDE -->|SHOOT| SHOTOUT{"Aproveitamento"}
  SHOTOUT -->|convertido| SCORE["+2 / +3
flip_possession()"]
  SHOTOUT -->|errado| REBOUND["rebote
slide seguinte"]

  REBOUND -.-> TURNOVER
  TURNOVER["Troca de posse
flip_possession()"] --> HANDLER

As perguntas do grafo ("passe chega?", "aproveitamento") não têm resposta fixa: cada uma é um sorteio ponderado pelos atributos de quem está em quadra, dos dois lados.

Exemplo: Duda, armador dos Tubarões, recebe a bola em HANDLER. Com 22s de posse, DECIDE favorece PASS ou MOVE. Se ele driblar e segurar a bola, o grafo volta para DECIDE — a posse continua até um estado terminal.

Este é o mapa da seção: state_machine.py não implementa esse grafo como uma estrutura de dados — é um laço com if/elif que caminha sobre esses mesmos estados. Os próximos slides abrem cada aresta (ação do condutor, passe, drible, arremesso, rebote) com o peso real por trás do sorteio.
